# Hybrid Bus Ticketing System: functional demo

A React + Vite web app for a UX assessment project. It is a **functional demonstration**, not a real ticketing system:
fares and the route are illustrative, **no payment is processed**, and **no physical printer is contacted** (printing is simulated in Demo mode).

## Pages
| Route | What it does |
|---|---|
| `#conductor` | Conductor-first dashboard: 6 destinations, 1 to 5 passengers, live fare, Issue, pending / issued / failed / STATUS UNKNOWN states, same-ticket retry, hold / resume / discard, recent tickets, demo printer controls |
| `#passenger` | Passenger self-service: destination, count, fare, review, confirm (no payment), digital ticket with QR, "my tickets" list |
| `#verify` | Ticket verification by typed ID or camera QR scan; results: valid, invalid, already used, unknown |
| `#settings` | Editable fare table (names and fares, validated) |

## Run locally
Requires Node 18+.
```bash
npm install
npm run dev        # http://localhost:5173
npm test           # unit tests (node:test) + UI interaction tests (vitest + jsdom)
npm run build      # production build -> dist/
npm run preview    # serve the production build locally
npm run build:single   # optional: one self-contained dist-single/index.html
```
Camera scanning needs HTTPS or `localhost`. The browser will ask for camera permission; if you deny it, re-enable it from the lock/camera icon in the address bar, or use manual ID entry.

## Deploy to a public Vercel URL
**Option A: GitHub**
1. Push this folder to a GitHub repository.
2. In Vercel: *Add New, Project*, import the repo. Vercel detects Vite (settings are also in `vercel.json`): build command `npm run build`, output directory `dist`.
3. Click *Deploy*. You get a `https://<project>.vercel.app` URL (HTTPS, so camera scanning works).

**Option B: CLI**
```bash
npm i -g vercel
vercel          # follow prompts, accept detected Vite settings
vercel --prod   # public production URL
```
Routing uses URL hashes (`#/verify`), so no rewrite rules are required.

## How the key rules are enforced
- **One open transaction:** while a transaction is open the Issue button is hidden; presses within 250 ms are ignored. Double-clicking creates exactly one ticket (tested).
- **Retry never duplicates:** retrying a failed/unknown print reuses the same ticket ID.
- **Unknown or failed is never "issued":** statistics, history counts and QR codes only use `status === 'issued'`. Reloading mid-print converts the transaction to STATUS UNKNOWN. The conductor must explicitly confirm, retry or cancel.
- **Tickets and verification:** IDs look like `HB-XXXXXX-C` (random plus a check character). QR codes are real, generated by the `qrcode` library from `HBTS1|ID|destination|count|total`. Verification trusts only the ID, looked up in this browser's saved tickets.

## Implemented
Conductor dashboard, fare table with validation, hold/resume/two-step discard, four ticket states, demo printer modes, ticket confirmation with real QR, history with issued-only stats, passenger booking flow and ticket details, verification with camera and manual entry, localStorage persistence (tickets, held, current transaction, fares, mode), responsive layout (sticky Issue bar on phones), keyboard focus styles, ARIA labels/live regions, empty/loading/error states.

## Limitations (please read)
- **Data is per browser.** localStorage is not synced. A ticket made on a passenger's phone cannot be verified on a conductor's device; the verifier reports such IDs as **UNKNOWN**. Cross-device verification needs a real backend (e.g. a small API plus database storing tickets and a "used" flag) that is not included.
- No real payment, printer, operator API, fare data, GPS or authentication. Anyone with browser access can edit local data.
- Passenger tickets are demo tickets, not valid on any bus. The four-second target, one-handed ergonomics and sunlight legibility are **not user-tested**.
- Single route and single boarding stop; no local-language labels; no left-hand mirror layout.
- Camera scanning was not run on a physical camera by the author; only the code path and error handling exist (jsQR decodes frames).
